# DevOps & Infrastructure Handoff Document

This document provides a comprehensive overview of the Cloud-Native Markdown Publishing Platform designed for the DevOps / Infrastructure engineering team. Use these requirements to finalize the Terraform infrastructure code and Jenkins CI/CD pipelines.

## 1. System Overview
- **Application Stack**: React (Vite) Frontend + Node.js (Express) Backend.
- **Microservices**: A single unified container executing both the Express API and Vite static serving, along with a background Chokidar-based Markdown file-watcher.
- **Database**: PostgreSQL (Relational Database).
- **Core Mechanism**: A background worker watches a directory (`RAW_ARTICLES_PATH`) for new `.md` files, parses them, and upserts them into Postgres.

## 2. Docker Containerization
- The application is shipped as a **single OCI-compliant Docker image** (using multi-stage builds).
- **Exposed Port**: `3000`
- **Mounts Needed**: A persistent volume must be mounted to the container at the directory specified by `RAW_ARTICLES_PATH` (default: `/app/raw_articles`). This is where users/systems will drop markdown files for processing.

## 3. Terraform (AWS) Requirements

The Terraform configuration must provision a robust, production-ready AWS environment. Minimum requirements:

### A. Networking (VPC)
- 1 x Custom VPC with DNS resolution enabled.
- 2 x Public Subnets (for Load Balancers / Bastion).
- 2 x Private Subnets (for App Containers and RDS Database).
- 1 x NAT Gateway (for outbound container traffic).

### B. Compute (ECS/EKS or EC2)
- **Primary Option (ECS Fargate)**: Deploy the Docker image as an ECS Task. 
  - *Crucial*: Because the app relies on a file watcher (Chokidar), you must provision an **Amazon EFS (Elastic File System)** volume and mount it to the task at `/app/raw_articles`. This allows scalable file dropping.
- **Alternative Option (EC2)**: If using EC2, mount an EBS volume or use EFS for the articles folder.

### C. Database (RDS)
- **Engine**: Amazon RDS for PostgreSQL (v15+).
- **Placement**: Private Subnets only.
- **Security**: Must only accept connections from the Compute Security Group.

### D. Security Groups & IAM
- **ALB SG**: Allow inbound HTTP (80) & HTTPS (443) from `0.0.0.0/0`.
- **App SG**: Allow inbound TCP `3000` ONLY from the ALB SG.
- **RDS SG**: Allow inbound TCP `5432` ONLY from the App SG.
- **IAM Roles**: Task Execution Role with ECR pull permissions, CloudWatch logs permissions, and EFS read/write access.

## 4. Jenkins Pipeline Requirements

The `Jenkinsfile` should codify a secure, automated CI/CD flow. 

### Required Tools/Plugins on Jenkins Agent:
- Node.js (v22+)
- Docker CLI
- AWS CLI
- Terraform CLI

### Pipeline Stages:
1. **Checkout**: Clone the repository from the main branch.
2. **Install & Verify**:
   - Run `npm ci`
   - Run `npm run lint`
3. **Build Code**:
   - Run `npm run build` (Compiles both Vite SPA and Express backend via esbuild).
4. **Build & Push Docker Image**:
   - `docker build -t <aws_account_id>.dkr.ecr.<region>.amazonaws.com/markdown-publisher:$GIT_COMMIT .`
   - Authenticate with AWS ECR: `aws ecr get-login-password | docker login ...`
   - Push image to ECR.
5. **Infrastructure Provisioning (Terraform)**:
   - `cd infrastructure/terraform`
   - `terraform init`
   - `terraform apply -auto-approve -var="image_tag=$GIT_COMMIT"` (Pass the new image tag to IaC to trigger rolling update).
6. **Post-Deploy Health Check**:
   - Ping the platform's `/api/articles` health endpoint.
   - Send Slack/Teams notification on Success/Failure.

## 5. Required Environment Variables

The deployment environment (ECS Task Definition or EC2 env vars) MUST inject the following variables securely at runtime:

- `NODE_ENV=production`
- `PORT=3000`
- `DATABASE_URL` (Generated by Terraform bridging RDS constraints: `postgres://<user>:<secret>@<rds_endpoint>:5432/<dbname>`)
- `RAW_ARTICLES_PATH` (Internal container path where the EFS volume is mounted, e.g., `/app/raw_articles`)

## 6. Edge/Proxy Considerations
- Nginx or AWS Application Load Balancer (ALB) must handle SSL termination.
- Ensure WebSocket or long-polling headers are supported if the real-time file watcher triggers frontend updates in future iterations.
- Caching: ALB/Nginx must bypass caching for `/api/*` but can aggressively cache static assets (`/assets/*`).
